# CLAUDE.md

Project brain — loaded into every session, so keep it short. State each rule
once. Add one under **Rules** whenever an agent gets something wrong.

---

## Build & Dev Commands

```bash
make check      # fmt + lint + test — run before every commit
make fmt lint test clean          # the individual stages
make manifest   # after editing a template-owned file, and after a version bump
```

`make check` must exit 0. A non-zero gate is a failure to fix, never to work
around or bypass.

## Tech Stack

Python via `uv` + `pyproject.toml`. Formatting, import order, docstring coverage,
and strict typing are enforced by `make check` — don't hand-audit what it covers.
The `python-standards` skill holds what a linter can't.

## Project Structure

What the directory names don't tell you:

- `openspec/specs/` is **canonical** — what the system does today — and is
  written only by `/archive-change`. `openspec/changes/` is work in flight.
- `.harness/` is template-owned (docs, evals, scripts, manifest). Editing
  anything there means running `make manifest`.
- Each feature dir under `src/` carries its own `CLAUDE.md`: stable facts only —
  purpose, entry points, invariants, gotchas; ~30 lines. Never implementation
  status (a change's `tasks.md` is that record), and never `@import` them here,
  because imports load eagerly and defeat the lazy loading they exist for.

## Change Lifecycle

`/crystallize` → `/dev-change <slug> <group>` → `/review` → `/commit-push-pr`
→ `/archive-change <slug>`. Five human gates: intent, spec+tasks, the review
before any commit, PR merge, archived spec diff.

- One `## N` task group in `tasks.md` = one branch = one PR. `/dev-change`
  claims a group by winning the race to create `feat/<slug>-g<N>`; **branch
  existence is the mutex**. Worktrees are opt-in (`--worktree`) and only pay
  for themselves when several sessions run at once.
- **The task group is the plan** — `/dev-change` implements it directly rather
  than re-planning it (Superpowers `test-driven-development` per task), then
  runs `make check`, dispatches the `verifier` agent, and **stops without
  committing**. The human runs `/review`, then `/commit-push-pr`. No agent
  commits or opens a PR on its own.
- After every group merges, `/archive-change <slug>` merges the delta specs into
  `openspec/specs/` and archives the change folder.
- Enter the loop through `/crystallize`; `/opsx:*` and `openspec-*` are
  OpenSpec's vendor tooling, regenerated by `openspec update`.

## Retrieval Protocol

For "what does the system do today?", read `openspec list --specs` for the index,
then open only the named capability files. Never bulk-read `openspec/` or `docs/`
— the whole loop exists so context loads per-change, not per-project.

## Git Strategy

- Branches: `feat/{change-slug}-g{N}`, `fix/{slug}`, `chore/{slug}`
- Commits: `type(scope): description`; PR body is `.github/pull_request_template.md`.
  Conventions: `.harness/docs/commits-and-prs.md`. Nothing reaches `main` unmerged.
- Diff a branch against `git merge-base main HEAD`, never bare `git diff main` —
  a moved `main` otherwise shows up inverted as noise.

## Environment Variables

**Never read `.env`** — the `pre_tool_env_guard.py` hook blocks it across Read,
Glob, LS, Grep, and Bash. Read `.env.template` instead; reference variables by name
via `os.environ` or pydantic `BaseSettings`.

## Rules

- **Never edit `openspec/specs/` directly.** All behaviour changes enter through
  `openspec/changes/`, and land only via `/archive-change`.
- If implementation shows a spec assumption is wrong, never silently fix the code
  around it: amend the active change's delta if the correction is small, open a
  new change if it is large. If which one is unclear, stop and ask.
- When implementation departs from `tasks.md`, update it in the same commit. It
  is an audit artifact PR review checks the diff against, not scaffolding.
- When a change or spec leaves a real ambiguity unresolved — architectural
  direction, contradictory requirements, a non-obvious security tradeoff — stop
  and ask the user. Do not guess, and do not widen scope to route around it.
